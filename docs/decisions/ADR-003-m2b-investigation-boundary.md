# ADR-003: отдельная граница расследования M2b

Дата: 2026-09-11. Статус: принято для реализации.

## Причина и совместимость с trial

Владелец проводит семидневный real-host trial M2a отдельно и разрешил начать M2b.
AI требует нового export/action contract, но не изменения наблюдений M2a.
Добавляем versioned evidence/analysis schemas и отдельную AI-конфигурацию.
SQLite остаётся v2, observation/config/detector versions и fingerprint M2a не меняются.
Существующие команды и sensors сохраняют поведение; `investigate` читает SQLite
через отдельное read-only соединение, без миграций, audit writes и retention.
Trial можно продолжать старым runtime. Новые результаты AI не являются результатами
детектора и не участвуют в его метриках; не переписываем историческое evidence.

## Решение

Стандартная библиотека, отдельные evidence, policy/application и provider modules.
В pack входят только выбранный alert, связанные записи, provenance/время/полнота,
детерминированные ограничения и подготовленное руководство. Произвольные metadata
строки заменяются локальными opaque aliases; это намеренная потеря деталей ради privacy.
Не используем regex как гарантию удаления secrets. Raw DB/history и свободные причины
не экспортируются. Перед каждым новым запросом показывается точное тело, route,
лимиты и digest согласия. Изменение evidence или параметров требует нового согласия.

Типизированные операции ограничены alert, связанными observations, конкретным baseline,
подготовленным runbook и узкой историей того же объекта. Во время trial повторный сбор
через AI запрещён: владелец отдельно использует существующий `sec scan`, затем начинает
новое расследование. Реестр не предоставляет collectors, shell/SQL/URL/path или mutations.
Это сужение доступной части разрешённого реестра, а не расширение sensors M2a.

Один вызов по умолчанию, максимум пять; конечные input/output/token/time/cost limits,
без retry/cloud escalation. Ошибки, исчерпание бюджета и невалидные ссылки возвращают
статическое объяснение. Model output никогда не меняет severity/lifecycle/baseline.
Ответ остаётся недоверенной гипотезой даже после проверки схемы и evidence IDs.

OpenRouter имеет фиксированный HTTPS endpoint, явный provider allowlist, запрет
fallback/data collection, ZDR и price caps. Локальный кандидат — уже установленный
Ollama на фиксированном loopback endpoint; без pull/install/start и без cloud models.
Реальная совместимость и выбор модели требуют отдельных измерений, не вывода по GPU.
Deadline транспорта обеспечивается отдельным ограниченным дочерним процессом;
он не имеет tools и получает только подготовленный запрос и нужный credential.

## Альтернативы и последствия

Не добавляем AI settings в Config v1: это изменило бы fingerprint и интерпретацию trial.
Не используем writable Store для расследования: даже его constructor выполняет PRAGMA
и миграции. Не сохраняем prompts/model text в watchdog DB; CLI выдаёт ограниченный
analysis record, который владелец может сохранить локально. Нет UI/vector DB/M2c/M3.

Read-only соединение кратко удерживает snapshot при подготовке pack и отпускает его
до сетевого вызова. Same-UID tampering, правдивость model text, provider billing/privacy
и надёжность внешнего local runtime не становятся доказанными свойствами приложения.
Транспортный timeout не отменяет уже начавшийся биллинг удалённого запроса. Для облака
нужен также отдельный ограниченный API key; зарезервированный расход не возвращается
в бюджет после ambiguous failures. Human review русского объяснения обязателен.
